1017 权重与部署 Deployment notes

本页只整理 1017 权重的本地方案和效果。

✓

◷部署 1017 的注意点
社区汇总
  • 不能混用 Engram 表。请使用与 1017 权重及量化包匹配的 Engram 表。
  • 没有 Jinja chat 模板。1017 仓库未带 chat_template.jinja，服务端需 --tokenizer-mode deepseek_v41 或用 encoding/encoding.py。
  • 注意 top_p 设置。1017 使用 1.0；部分 Flare 版本上的配置不匹配可能导致请求失败。
  • 推理循环未修复。长上下文（社区反馈 300K 以上更频繁）仍会进入复读；建议限上下文、提前压缩或加 repeat guard。
  • 高并发偶发报错。高并发（C16+）下约每 700–1,000 次持续请求出现一次 device error 6；可把并发限在 8、关闭 MTP，或接受约 0.1% 的失败重试。

LIMITS & PITFALLS / 04

跑不起来、会掉速的边界 Negative results

这些是社区真实踩过的坑，比峰值速度更值得先看。

◫装不下 / 掉速
实测报告
  • 原生 510GB 权重塞不进 2×96GB。常驻权重要求约 145GiB/卡；2 卡必须 ≤3bpw 量化或把专家卸载到主机内存。
  • 3×96GB 也要卸载。约 101GiB/GPU，需把约 1/3 专家停在主机内存，靠路由命中率撑住。
  • CPU/SSD 卸载会塌缩吞吐。3 卡 CPU 卸载被作者形容为「tps 掉得很严重」。
  • 引擎版本门槛高。SM120 上跑官方 NVFP4 需要 vLLM PR 61530/60762 + flashinfer 0.7.2；stock vLLM 0.32 不可用（修复后 127→214 tok/s）。
◷长上下文 / 稳定性
社区日报
  • 4,096-token prefill 块在约 399K 输入处失败。发布者的默认值是 2,048。
  • Flare gb202 是 TP4 专属包。4 卡是硬要求；跨两个 PCIe switch 曾触发 120 秒启动超时。
  • CSF 量化包在 Spark 上慢 5–20%。省空间不等于免费。
  • DGX Spark 散热与坏卡。社区报告约 88°C、限频到 2.2GHz 可降到 80°C；8 台里有 1 台内存报错的案例。
  • 12V-2x6 供电接口有熔化报告。RTX PRO 6000 用户在限功耗 500W 下仍报告接口接近熔化；Tom's Hardware 指出该连接器问题仍在持续。多卡整机务必核对供电线材与单路负载。（2026-11-10 社区日报）
